    2-1-2. ReplicaSet & Deployment 실습¶

    실습 목표¶

    • ReplicaSet이 Pod를 자동으로 복구하는 동작을 확인한다.
    • Deployment로 롤링 업데이트와 롤백을 실습한다.
    • 스케일 조정으로 Pod 수를 늘리고 줄인다.

    공식 문서 참고¶

    • ReplicaSet 공식 문서
    • Deployment 공식 문서
    • kubectl 치트시트

    1) ReplicaSet 실습¶

    ReplicaSet은 지정한 수만큼 Pod를 항상 유지합니다.

    replicaset.yaml 파일을 만듭니다.

    apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: nginx-rs
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx-rs
  template:
    metadata:
      labels:
        app: nginx-rs
    spec:
      containers:
        - name: nginx
          image: nginx:1.25
          ports:
            - containerPort: 80

    kubectl apply -f replicaset.yaml
kubectl get replicasets          # 약어: kubectl get rs
kubectl get pods --show-labels   # 약어: kubectl get po --show-labels

    Pod 삭제 후 자동 복구 확인¶

    Pod 하나를 삭제합니다.

    kubectl get pods -l app=nginx-rs         # 약어: kubectl get po -l app=nginx-rs
kubectl delete pod <pod이름 중 하나>
kubectl get pods -l app=nginx-rs -w      # 즉시 새 Pod가 생성되는 것을 실시간 확인

    Ctrl+C로 watch 모드 종료.

    ReplicaSet이 replicas: 3을 유지하기 위해 삭제된 Pod를 즉시 새로 만듭니다.

    Label을 바꾸면 ReplicaSet 관리에서 빠짐¶

    ReplicaSet은 label selector로 Pod를 관리합니다. Pod의 label을 바꾸면 ReplicaSet이 더 이상 그 Pod를 자신의 Pod로 인식하지 않아 새 Pod를 추가로 생성합니다.

    # Pod 중 하나의 label 변경
kubectl label pod <pod이름> app=orphan --overwrite
kubectl get pods --show-labels    # Pod가 4개가 됨 (고아 Pod 1개 + ReplicaSet 관리 3개)

    확인 후 고아 Pod 삭제:

    kubectl delete pod -l app=orphan

    YAML로 replicas 수정 후 apply¶

    replicaset.yaml을 열어 replicas 값을 3 → 5로 수정합니다.

    spec:
  replicas: 5   # 3 → 5로 변경

    저장 후 다시 apply합니다.

    kubectl apply -f replicaset.yaml
kubectl get rs                     # DESIRED가 5로 바뀐 것 확인
kubectl get po -l app=nginx-rs     # Pod가 5개로 늘어난 것 확인

    kubectl apply는 변경된 부분만 감지해서 반영합니다. 숫자를 다시 3으로 줄이면 Pod 2개가 자동으로 종료됩니다.

    ReplicaSet 실습 정리¶

    kubectl delete -f replicaset.yaml
kubectl get po                     # Pod가 모두 삭제되었는지 확인

    2) Deployment 생성¶

    Deployment는 ReplicaSet을 한 단계 감싸며, 롤링 업데이트·롤백 기능을 추가로 제공합니다.

    dry-run으로 Deployment YAML 뽑기¶

    Pod와 마찬가지로 --dry-run=client -o yaml로 Deployment YAML의 시작점을 만들 수 있습니다.

    kubectl create deployment rollout-deploy \
  --image=skilleat/rollout-demo:mystery \
  --replicas=3 \
  --dry-run=client -o yaml > deploy-rollout.yaml

    출력 예시:

    apiVersion: apps/v1
kind: Deployment
metadata:
  name: rollout-deploy
spec:
  replicas: 3
  selector:
    matchLabels:
      app: rollout-deploy
  template:
    metadata:
      labels:
        app: rollout-deploy
    spec:
      containers:
      - image: skilleat/rollout-demo:mystery
        name: rollout-deploy

    도전 과제 — 포트를 직접 찾아 접속하기¶

    이 이미지는 포트가 공개되지 않습니다

    skilleat/rollout-demo:mystery 이미지는 흔하지 않은 포트로 실행됩니다. containerPort 없이 그대로 배포한 뒤, 스스로 포트를 찾아서 브라우저로 접속해보세요.

    1단계 — 그대로 배포

    kubectl apply -f deploy-rollout.yaml
kubectl get deploy               # 약어: kubectl get deploy
kubectl get po                   # Pod가 Running 상태인지 확인

    2단계 — port-forward로 접속

    찾은 포트로 직접 연결합니다.

    kubectl port-forward deployment/rollout-deploy <찾은포트>:<찾은포트>

    브라우저에서 http://localhost:<찾은포트> 접속 후 Ctrl+C로 종료.

    4단계 — 정리

    kubectl delete -f deploy-rollout.yaml
kubectl get po                   # Pod 삭제 확인

    v1.0.0으로 배포 (파란색)¶

    도전 과제가 끝났으면 deploy-rollout.yaml을 VS Code에서 열어 아래와 같이 수정합니다. 이미지를 v1.0.0으로 바꾸고 containerPort를 추가합니다.

    apiVersion: apps/v1
kind: Deployment
metadata:
  name: rollout-deploy
spec:
  replicas: 3
  selector:
    matchLabels:
      app: rollout
  template:
    metadata:
      labels:
        app: rollout
    spec:
      containers:
        - name: app
          image: skilleat/rollout-demo:v1.0.0
          ports:
            - containerPort: 8080

    kubectl apply -f deploy-rollout.yaml
kubectl get deploy               # 약어: kubectl get deploy
kubectl get rs                   # 약어: kubectl get rs
kubectl get po --show-labels     # 약어: kubectl get po --show-labels

    Deployment → ReplicaSet → Pod 계층 구조를 확인합니다.

    kubectl describe deploy rollout-deploy    # NewReplicaSet 이름 확인
kubectl describe rs <rs이름>              # 관리 중인 Pod 확인

    배포 후 port-forward로 파란색 페이지를 확인합니다.

    kubectl port-forward deployment/rollout-deploy 8080:8080

    http://localhost:8080 접속 후 Ctrl+C로 종료.

    3) 롤링 업데이트¶

    v2.0.0으로 업데이트합니다. v2.0.0은 초록색 배경 페이지를 반환합니다.

    새 터미널을 열어 먼저 Pod 변화를 실시간으로 감시합니다.

    kubectl get pods -w    # 새 터미널에서 실행 — 교체 과정을 실시간으로 관찰

    기존 터미널에서 이미지를 변경합니다.

    kubectl set image deployment/rollout-deploy app=skilleat/rollout-demo:v2.0.0
kubectl rollout status deployment/rollout-deploy

    watch 중인 터미널에서 구 Pod(v1.0.0)가 종료되고 새 Pod(v2.0.0)가 생성되는 과정이 보입니다. 확인 후 Ctrl+C로 watch 종료.

    완료 후 다시 port-forward로 확인합니다. 초록색 페이지로 바뀌어 있어야 합니다.

    kubectl port-forward deployment/rollout-deploy 8080:8080

    이미지 버전 확인:

    kubectl describe deployment rollout-deploy | grep Image

    4) 롤백¶

    초록색 → 파란색으로 되돌립니다.

    kubectl rollout history deployment/rollout-deploy    # 변경 히스토리

    출력 예시:

    REVISION  CHANGE-CAUSE
1         <none>
2         <none>

    CHANGE-CAUSE가 <none>으로 보이는 이유

    변경 이유를 별도로 기록하지 않았기 때문입니다. kubernetes.io/change-cause 어노테이션을 직접 달아주면 이력에 표시됩니다.

    # apply 직후 바로 어노테이션 추가
kubectl annotate deployment/rollout-deploy kubernetes.io/change-cause="v1.0.0 초기 배포"
kubectl annotate deployment/rollout-deploy kubernetes.io/change-cause="v2.0.0 업데이트" --overwrite

    이후 kubectl rollout history를 다시 실행하면 아래처럼 보입니다.

    REVISION  CHANGE-CAUSE
1         v1.0.0 초기 배포
2         v2.0.0 업데이트

    kubectl rollout undo deployment/rollout-deploy       # 이전 버전(v1.0.0)으로 복귀
kubectl rollout status deployment/rollout-deploy
kubectl describe deployment rollout-deploy | grep Image    # v1.0.0 복귀 확인

    port-forward로 다시 확인하면 파란색 페이지로 돌아옵니다.

    kubectl port-forward deployment/rollout-deploy 8080:8080

    5) 스케일 조정¶

    kubectl scale deployment rollout-deploy --replicas=5   # 약어: kubectl scale deploy rollout-deploy --replicas=5
kubectl get pods                                        # 약어: kubectl get po
kubectl scale deployment rollout-deploy --replicas=2
kubectl get pods

    정리 (리소스 삭제)¶

    kubectl delete -f replicaset.yaml
kubectl delete -f deploy-rollout.yaml

    핵심 정리¶

    항목 Pod 단독 ReplicaSet Deployment
    복제본 관리 수동 자동 자동
    장애 복구 없음 자동 재생성 자동 재생성
    롤링 업데이트 불가 불가 내장 지원
    실사용 권장 디버깅용 거의 직접 사용 안 함 프로덕션 배포
