## 서비스 구조 이해

배포를 시작하기 전에, 개발팀이 만든 서비스가 어떻게 동작하는지 먼저 파악하세요.

### 사용자 요청 흐름

```
사용자 브라우저
    │
    │  ① 단축 URL 생성 요청 (긴 URL 입력)
    ▼
[ app 컨테이너 : FastAPI ]
    │  ② 단축 코드 생성 후 DB에 저장
    ▼
[ db 컨테이너 : PostgreSQL ]
    │
    │  ③ 저장 완료 응답
    ▼
[ app 컨테이너 ]
    │  ④ 단축 URL 반환 → 브라우저에 표시
    ▼
사용자 브라우저

─────────────────────────────────────

사용자가 단축 URL 클릭 시:

사용자 브라우저
    │  ⑤ 단축 코드로 접속
    ▼
[ app 컨테이너 ]
    │  ⑥ DB에서 원본 URL 조회 + 클릭 수 +1
    ▼
[ db 컨테이너 ]
    │  ⑦ 원본 URL 반환
    ▼
[ app 컨테이너 ]
    │  ⑧ 원본 URL로 리다이렉트
    ▼
사용자 브라우저 (원본 사이트로 이동)
```

### 소스 코드 구성

repo를 clone해서 구조를 직접 확인하세요.

```
url-shortener-lab/
├── app/
│   └── main.py          ← FastAPI 앱 (URL 생성 / 조회 / 리다이렉트 API)
├── postgres/
│   └── init.sql         ← DB 최초 실행 시 테이블 생성 스크립트
├── requirements.txt     ← Python 패키지 목록
└── (Dockerfile 없음)    ← 직접 작성 필요
```

!!! note "설계 먼저, 명령어는 나중에"
    위 흐름을 보고 **컨테이너가 몇 개 필요한지**, **어떻게 연결되어야 하는지**,
    **무엇을 보존해야 하는지** 먼저 종이에 그려보세요.
    설계가 끝나면 구현은 빠릅니다.

## 요구사항

### 개발팀 인수인계 기술 정보

| 항목 | 내용 |
|------|------|
| 언어 | Python 3.12 |
| 프레임워크 | FastAPI (uvicorn으로 실행) |
| 앱 실행 명령어 | `uvicorn app.main:app --host 0.0.0.0 --port 8000` |
| Dockerfile CMD 형식 | `CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]` |
| 앱 listen 포트 | 8000 |
| DB | PostgreSQL 16, DB 이름: `shortener` |
| DB 연결 환경변수 | `DATABASE_URL` (앱 컨테이너에 주입 필요, 아래 설명 참고) |
| DB 초기화 스크립트 | repo 내 `postgres/init.sql` |

### DATABASE_URL 구성 방법

앱은 DB에 접속하기 위해 `DATABASE_URL` 환경변수를 읽습니다. 형식은 아래와 같습니다.

```
postgresql://USER:PASSWORD@HOST:5432/shortener
```

각 항목을 채우는 방법:

| 항목 | 설명 |
|------|------|
| `USER` | PostgreSQL 컨테이너에 설정한 `POSTGRES_USER` 값 (미설정 시 기본값: `postgres`) |
| `PASSWORD` | PostgreSQL 컨테이너에 설정한 `POSTGRES_PASSWORD` 값 |
| `HOST` | **PostgreSQL 컨테이너 이름** — 같은 Docker 네트워크 안에서는 컨테이너 이름이 곧 호스트명입니다 |
| `shortener` | DB 이름 (고정값) |

!!! tip "HOST가 IP가 아닌 이유"
    같은 Docker 네트워크에 속한 컨테이너끼리는 **컨테이너 이름**으로 서로를 찾을 수 있습니다.
    예를 들어 DB 컨테이너 이름을 `postgres`로 지정했다면, HOST 자리에 `postgres`를 넣으면 됩니다.

### 운영 요구사항

!!! warning "구현 방법은 스스로 결정하세요. 아래는 **무엇을** 해야 하는지만 기술합니다."

1. **데이터 영속성** — 컨테이너 또는 호스트가 재시작되어도 기존 단축 URL이 동작해야 합니다.
2. **네트워크 보안** — DB는 외부에서 직접 접근할 수 없어야 합니다. (보안팀 요구사항)
3. **자동 복구** — 컨테이너가 비정상 종료되면 자동으로 재시작되어야 합니다.
4. **상태 확인** — 서비스가 정상인지 외부에서 확인할 수 있어야 합니다.
5. **이미지 보관** — 빌드한 이미지는 반드시 본인의 ACR에 push해서 보관해야 합니다.

### 사용할 공식 이미지

**PostgreSQL 16**
→ [https://hub.docker.com/_/postgres](https://hub.docker.com/_/postgres)

Docker Hub 페이지에서 다음 섹션을 찾아보세요:

- **Environment Variables** — PostgreSQL 컨테이너는 `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` 환경변수로 DB를 초기 설정합니다.
- **Initialization scripts** — `init.sql`을 컨테이너의 `/docker-entrypoint-initdb.d/` 경로에 마운트하면 최초 실행 시 자동으로 실행됩니다.
- **Where to Store Data** — PostgreSQL 컨테이너는 데이터를 `/var/lib/postgresql/data` 경로에 저장합니다. 이 경로를 볼륨으로 마운트하면 컨테이너가 삭제되어도 데이터가 유지됩니다.

**Python 3.12**
→ [https://hub.docker.com/_/python](https://hub.docker.com/_/python)

## 완료 기준

과제가 완료되면 아래 3가지를 직접 검증하고 강사를 불러주세요.

- [ ] **1. 단축 URL 생성** — 브라우저에서 본인 VM IP로 서비스에 접속해 단축 URL을 생성할 수 있다.
- [ ] **2. 리다이렉트 및 클릭 수** — 생성한 단축 URL로 접속하면 원본 URL로 이동하고, 클릭 수가 올라간다.
- [ ] **3. 재부팅 후 데이터 유지** — `docker restart` 또는 VM 재부팅 후에도 기존 단축 URL이 동작한다.
- [ ] **4. 네트워크 보안 검증** — 호스트에서 DB 포트로 직접 접속을 시도했을 때 연결이 거부되어야 한다.

    ```
    psql -h localhost -p 5432 -U postgres
    # → 연결 실패가 나오면 올바르게 구성된 것
    ```

- [ ] **5. ACR 이미지 확인** — `az acr repository list --name <본인ACR이름>`에서 push한 이미지가 보여야 한다.
