## 1) kubectl run으로 Pod 빠르게 생성

YAML 없이 명령어 한 줄로 Pod를 만들 수 있습니다.

```bash
kubectl run nginx-pod --image=nginx:1.25
```

상태 확인:

```bash
kubectl get pods
kubectl get pods -o wide    # Pod IP 포함
```

### dry-run으로 YAML 미리 보기

`--dry-run=client -o yaml` 옵션을 붙이면 실제로 생성하지 않고 YAML만 출력합니다. YAML 작성이 익숙하지 않을 때 시작점으로 활용할 수 있습니다.

```bash
kubectl run test --image=nginx:1.25 --dry-run=client -o yaml
```

출력 예시:

```yaml
apiVersion: v1
kind: Pod
metadata:
  creationTimestamp: null
  labels:
    run: test
  name: test
spec:
  containers:
  - image: nginx:1.25
    name: test
    resources: {}
  dnsPolicy: ClusterFirst
  restartPolicy: Always
```

이 출력을 파일로 저장해서 편집하면 됩니다.

```bash
kubectl run test --image=nginx:1.25 --dry-run=client -o yaml > pod-test.yaml
```

## 2) YAML로 Pod 생성

`pod-nginx.yaml` 파일을 확인합니다.

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
  labels:
    app: nginx
    env: lab
spec:
  containers:
    - name: nginx
      image: nginx:1.25
      ports:
        - containerPort: 80
```

```bash
kubectl apply -f pod-nginx.yaml
kubectl get pods
kubectl describe pod nginx-pod
```

`describe` 출력에서 확인:

- `Status`: Running
- `IP`: Pod에 할당된 내부 IP
- `Labels`: 부여된 label 목록
- `Events`: 이미지 pull → 컨테이너 시작 과정

### 로그 확인

```bash
kubectl logs nginx-pod
kubectl logs nginx-pod -f    # 실시간 스트리밍
```

### Pod 내부 접속

> `--` 는 kubectl 옵션의 끝을 알리는 구분자입니다. 이후에 오는 `bash`는 kubectl이 아닌 컨테이너 안에서 실행할 명령어로 전달됩니다. Docker의 `docker exec -it nginx-pod bash`와 달리 kubectl은 자체 옵션과 컨테이너 명령어를 `--`로 분리합니다.

```bash
kubectl exec -it nginx-pod -- bash
# 컨테이너 내부
nginx -v
curl localhost
exit
```

### curl 이미지로 Pod 간 통신 확인

> `curlimages/curl` 은 `curl` 명령어만 포함된 초경량 이미지로, 클러스터 내부에서 HTTP 통신을 빠르게 테스트할 때 사용합니다.

`nginx-pod`의 IP를 확인한 뒤, curl 이미지를 실행해 해당 IP로 요청을 보냅니다.

```bash
kubectl get pods -o wide    # nginx-pod의 IP 확인 (예: 10.1.0.5)
```

```bash
kubectl run curl-test --image=curlimages/curl:latest --restart=Never -it --rm \
  -- curl http://10.1.0.5
```

nginx 응답 HTML이 출력되면 성공입니다. `--rm` 옵션으로 종료 시 Pod가 자동 삭제됩니다.

### Pod 삭제 후 IP 변화 관찰

```bash
kubectl delete pod nginx-pod
kubectl apply -f pod-nginx.yaml
kubectl get pods -o wide    # 새 IP가 할당됨을 확인
```

> **포인트**: Pod를 재생성하면 IP가 바뀝니다. 그래서 Service가 필요합니다.

## 3) 멀티 컨테이너 Pod

하나의 Pod에 컨테이너를 여러 개 넣을 수 있습니다. 같은 네트워크와 스토리지를 공유하므로 `localhost`로 서로 통신합니다.

### command 필드란?

`command`는 컨테이너가 시작될 때 실행할 명령어를 직접 지정하는 필드입니다. Docker의 `ENTRYPOINT`에 해당합니다.

| 필드 | Docker 대응 | 설명 |
|---|---|---|
| `command` | `ENTRYPOINT` | 실행할 명령어 (이미지 기본값 덮어씀) |
| `args` | `CMD` | 명령어에 전달할 인자 |

`command`를 지정하지 않으면 이미지에 정의된 기본 명령어가 실행됩니다. 아래 예시에서 sidecar 컨테이너는 이미지 기본 동작 대신 `sh -c "while true; ..."` 쉘 스크립트를 실행합니다.

```yaml
command: ["sh", "-c", "while true; do echo $(date) $(curl -s localhost); sleep 5; done"]
#          ↑실행파일   ↑sh에 전달되는 인자: 5초마다 localhost(=nginx)에 curl 요청
```

`pod-multi.yaml` 파일을 만듭니다.

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: multi-pod
  labels:
    app: multi
spec:
  containers:
    - name: nginx
      image: nginx:1.25
      ports:
        - containerPort: 80
    - name: sidecar
      image: curlimages/curl:latest
      command: ["sh", "-c", "while true; do echo $(date) $(curl -s localhost); sleep 5; done"]
```

```bash
kubectl apply -f pod-multi.yaml
kubectl get pods    # READY 2/2 확인
```

각 컨테이너 로그를 따로 확인합니다.

```bash
kubectl logs multi-pod -c nginx      # nginx 컨테이너 로그
kubectl logs multi-pod -c sidecar    # sidecar 컨테이너 로그
```

sidecar가 `localhost`로 nginx에 접근하여 응답을 받는 것을 확인합니다.

특정 컨테이너 내부 접속:

```bash
kubectl exec -it multi-pod -c nginx -- bash
```

## 4) Label과 --show-labels

Label은 K8s 리소스에 붙이는 키-값 태그입니다. Deployment가 Pod를 선택하거나 Service가 트래픽을 보낼 대상을 찾을 때 label을 기준으로 합니다.

### label 확인

```bash
kubectl get pods --show-labels
```

출력 예시:

```
NAME        READY   STATUS    RESTARTS   AGE   LABELS
nginx-pod   1/1     Running   0          2m    app=nginx,env=lab
multi-pod   2/2     Running   0          1m    app=multi
```

### label 기준으로 필터링

`-l` 옵션으로 특정 label을 가진 Pod만 조회할 수 있습니다.

```bash
kubectl get pods -l app=nginx
kubectl get pods -l env=lab
kubectl get pods -l app=nginx,env=lab    # 두 조건 모두 만족
```

### label 추가 / 변경 / 삭제

```bash
kubectl label pod nginx-pod version=v1          # label 추가
kubectl label pod nginx-pod env=production --overwrite   # label 변경
kubectl label pod nginx-pod version-            # label 삭제 (키 뒤에 - 붙임)
kubectl get pods --show-labels                  # 변경 결과 확인
```

## 핵심 정리

| 개념 | 설명 |
|---|---|
| Pod | K8s에서 배포 가능한 가장 작은 단위, 컨테이너를 1개 이상 포함 |
| 멀티 컨테이너 | 같은 Pod 내 컨테이너는 `localhost`로 통신, 스토리지 공유 |
| Label | 리소스에 붙이는 키-값 태그, Service·Deployment의 대상 선택 기준 |
| Pod IP | 재생성 시 변경됨 → Service가 필요한 이유 |

## 트러블슈팅

| 증상 | 확인 사항 |
|---|---|
| Pod `ImagePullBackOff` | 이미지 이름/태그 오타 또는 네트워크 문제 |
| Pod `Pending` | 노드 리소스 부족 (`kubectl describe pod` 이벤트 확인) |
| Pod `CrashLoopBackOff` | 컨테이너 실행 오류 (`kubectl logs <pod>` 확인) |
| READY `2/2` 안됨 | `kubectl describe pod`에서 각 컨테이너 상태 확인 |
