# 1-1. 실습 환경 설정 (Docker Desktop / Rancher Desktop)

## 실습 목표

- Docker Desktop 또는 Rancher Desktop에서 로컬 Kubernetes 클러스터를 활성화한다.
- kubectl이 클러스터에 연결되었음을 확인한다.
- 이후 모든 실습의 기반 환경을 준비한다.

## 준비물

- macOS 또는 Windows PC
- 인터넷 연결
- 관리자 권한

---

## 옵션 A — Docker Desktop으로 설정

### 1) Docker Desktop 설치

1. [Docker Desktop 공식 다운로드](https://www.docker.com/products/docker-desktop/) 페이지에서 운영체제에 맞는 버전을 설치합니다.
2. 설치 후 Docker Desktop을 실행합니다.

### 2) Kubernetes 활성화

1. 오른쪽 상단 톱니바퀴(Settings)를 클릭합니다.
2. 왼쪽 메뉴에서 **Kubernetes**를 선택합니다.
3. **Enable Kubernetes** 체크박스를 활성화합니다.
4. **Apply & Restart** 버튼을 클릭합니다.
5. 하단 상태 표시줄에 초록색 Kubernetes 아이콘이 나타날 때까지 기다립니다. (1~3분 소요)

### 3) 연결 확인

터미널에서 실행합니다.

```bash
kubectl config current-context
```

`docker-desktop`이 출력되면 정상입니다.

```bash
kubectl get nodes
```

```
NAME             STATUS   ROLES           AGE   VERSION
docker-desktop   Ready    control-plane   1m    v1.29.x
```

## 옵션 B — Rancher Desktop으로 설정

### 1) Rancher Desktop 설치

1. [Rancher Desktop 공식 다운로드](https://rancherdesktop.io/) 페이지에서 설치 파일을 다운로드합니다.
2. 설치 후 실행합니다.
3. 초기 설정 화면에서 아래를 선택합니다.
   - **Container Runtime**: `dockerd (moby)` — Docker 명령어 호환
   - **Kubernetes Version**: 최신 안정 버전 (예: v1.29.x)

### 2) kubeconfig 자동 설정

Rancher Desktop을 설치하고 실행하면 클러스터 접속 정보가 **자동으로** kubeconfig 파일에 추가됩니다. 별도 설정 없이 바로 `kubectl`을 사용할 수 있습니다.

=== "PowerShell"
    kubeconfig 파일 위치를 확인합니다.

    ```powershell
    "$env:USERPROFILE\.kube\config"
    ```

    파일 내용을 확인합니다.

    ```powershell
    Get-Content "$env:USERPROFILE\.kube\config"
    ```

=== "Bash"
    kubeconfig 파일 위치를 확인합니다.

    ```bash
    echo ~/.kube/config
    ```

    파일 내용을 확인합니다.

    ```bash
    cat ~/.kube/config
    ```

`rancher-desktop` 클러스터 항목이 포함되어 있으면 정상입니다.

### 3) 연결 확인

=== "PowerShell"
    ```powershell
    kubectl config current-context
    ```

    `rancher-desktop`이 출력되면 정상입니다.

    ```powershell
    kubectl get nodes
    ```

=== "Bash"
    ```bash
    kubectl config current-context
    ```

    `rancher-desktop`이 출력되면 정상입니다.

    ```bash
    kubectl get nodes
    ```

```
NAME                   STATUS   ROLES                  AGE   VERSION
lima-rancher-desktop   Ready    control-plane,master   2m    v1.29.x
```

## 공통 확인 사항

!!! tip "자동완성(Tab) 을 적극 활용하세요"
    `kubectl` 명령어 입력 중 **Tab** 키를 누르면 다음에 올 수 있는 서브커맨드 목록이 자동으로 채워집니다.
    클러스터에 실제로 존재하는 리소스 이름(Pod, Deployment 이름 등)도 Tab으로 완성되므로
    오타 없이 빠르게 명령어를 작성할 수 있습니다.

    자동완성을 활성화하려면 아래 설정을 한 번만 실행해 두면 됩니다.

    === "PowerShell"
        현재 세션에서 즉시 활성화합니다.

        ```powershell
        kubectl completion powershell | Out-String | Invoke-Expression
        ```

        PowerShell 시작 시 자동으로 불러오려면 프로필에 추가합니다.

        ```powershell
        kubectl completion powershell >> $PROFILE
        ```

        > `$PROFILE` 파일이 없으면 먼저 `New-Item -Path $PROFILE -Force` 로 생성하세요.

    === "Bash"
        현재 세션에서 즉시 활성화합니다.

        ```bash
        source <(kubectl completion bash)
        ```

        터미널을 열 때마다 자동으로 불러오려면 셸 설정 파일에 추가합니다.

        ```bash
        echo 'source <(kubectl completion bash)' >> ~/.bashrc
        source ~/.bashrc
        ```

    설정 후 `kubectl get ` 까지 입력하고 Tab을 두 번 누르면 `pods`, `deployments`, `services` 등
    사용 가능한 리소스 종류가 나열됩니다. 리소스 이름 입력 중에도 Tab을 누르면
    클러스터에 실제로 존재하는 오브젝트 이름이 자동으로 완성됩니다.

### kubectl 버전 확인

```bash
kubectl version --client
```

### 클러스터 전체 상태 확인

```bash
kubectl cluster-info
```

```
Kubernetes control plane is running at https://127.0.0.1:6443
```

### 노드 상세 정보 확인

`-o wide` 옵션을 붙이면 기본 출력보다 더 많은 정보를 한눈에 볼 수 있습니다.

```bash
kubectl get nodes -o wide
```

```
NAME             STATUS   ROLES           AGE   VERSION   INTERNAL-IP    OS-IMAGE         KERNEL-VERSION   CONTAINER-RUNTIME
docker-desktop   Ready    control-plane   5m    v1.29.x   192.168.65.3   Docker Desktop   6.6.x            docker://26.x.x
```

기본 `kubectl get nodes`와 비교해보세요. `-o wide`에서 추가로 보이는 항목은 다음과 같습니다.

| 추가 항목 | 설명 |
|---|---|
| `INTERNAL-IP` | 노드의 내부 IP 주소 |
| `OS-IMAGE` | 노드에서 사용 중인 OS |
| `KERNEL-VERSION` | 리눅스 커널 버전 |
| `CONTAINER-RUNTIME` | 컨테이너 실행 엔진 (docker, containerd 등) |

> `-o wide`는 `kubectl get pods`, `kubectl get nodes` 등 대부분의 리소스에 사용할 수 있습니다. 이후 실습에서도 자주 활용합니다.

## (선택) AKS 연결 — 추후 사용

로컬 환경에 익숙해진 후 Azure AKS로 전환할 때는 아래 명령어로 컨텍스트를 추가합니다.

```bash
az aks get-credentials --resource-group <rg이름> --name <aks이름>
kubectl config get-contexts        # 등록된 클러스터 목록 확인
kubectl config use-context <이름>  # 클러스터 전환
```

## Windows PowerShell 사용 시 참고 사항

> 이 모듈의 kubectl 명령어는 모두 PowerShell에서 동일하게 동작합니다.
> 단, 일부 셸 스크립트 문법은 차이가 있으므로 아래를 참고하세요.

| 상황 | macOS / Linux | Windows PowerShell |
|---|---|---|
| HTTP 요청 테스트 | `curl http://...` | `curl.exe http://...` |
| 텍스트 필터 | `kubectl ... \| grep "패턴"` | `kubectl ... \| Select-String "패턴"` |
| base64 인코딩 | `echo -n "값" \| base64` | `[Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes("값"))` |
| base64 디코딩 | `echo -n "값" \| base64 -d` | `[Text.Encoding]::UTF8.GetString([Convert]::FromBase64String("값"))` |
| 반복 요청 루프 | `while true; do curl ...; done` | `while ($true) { curl.exe ...; Start-Sleep 1 }` |

> **curl vs curl.exe**: PowerShell에서 `curl`은 `Invoke-WebRequest`의 별칭입니다. 일반 curl처럼 사용하려면 `curl.exe`를 사용하세요.

## 트러블슈팅

| 증상 | 확인 사항 |
|---|---|
| `kubectl: command not found` | Docker Desktop 재설치 또는 PATH 설정 확인 |
| `Unable to connect to the server` | Docker Desktop이 실행 중인지, Kubernetes가 활성화되었는지 확인 |
| 노드 상태 `NotReady` | 1~2분 후 재확인, 또는 Docker Desktop 재시작 |
| Rancher Desktop 노드 없음 | Rancher Desktop 앱이 완전히 시작될 때까지 대기 |
