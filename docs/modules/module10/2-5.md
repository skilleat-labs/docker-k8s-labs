# 2-5. 미니 블로그 3-tier 배포 실습

## 실습 목표

- Frontend(Nginx) · Backend(Node.js) · Database(MySQL) 3계층 애플리케이션을 K8s에 배포한다.
- ConfigMap과 Secret으로 설정을 분리한다.
- Service를 통해 각 계층이 서로 통신하는 구조를 구현한다.
- 실제 동작하는 API를 통해 DB 연동까지 확인한다.

---

## 아키텍처

```
사용자 (curl / 브라우저)
    ↓ localhost:30080 (NodePort)
backend-svc (NodePort :30080 → 8080)
    ↓ mysql-svc:3306
mysql-svc (ClusterIP :3306)
    ↓
mysql Deployment (MySQL × 1)
```

!!! note "이번 실습의 범위"
    이번 실습에서는 Backend API와 DB 연동에 집중합니다. Frontend(Nginx)는 별도 배포 없이 Backend API를 NodePort로 직접 노출하여 동작을 확인합니다.

| 역할 | 이미지 | 설명 |
|---|---|---|
| Backend | `skilleat/miniblog-api:v1.0.0` | Node.js Express, port 8080, MySQL 연동 |
| Database | `mysql:8.0` | 공식 MySQL 이미지 |

## 1) ConfigMap / Secret 배포

`blog-config.yaml` 파일을 만듭니다.

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: blog-config
data:
  DB_HOST: mysql-svc
  DB_PORT: "3306"
  DB_NAME: blogdb
  DB_USER: bloguser
```

`blog-secret.yaml` 파일을 만듭니다.

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: blog-secret
type: Opaque
stringData:
  DB_PASSWORD: blogpassword123
  MYSQL_ROOT_PASSWORD: rootpassword123
```

```bash
kubectl apply -f blog-config.yaml
kubectl apply -f blog-secret.yaml
```

## 2) MySQL 배포

`mysql-deploy.yaml` 파일을 만듭니다.

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: mysql
spec:
  replicas: 1
  selector:
    matchLabels:
      app: mysql
  template:
    metadata:
      labels:
        app: mysql
    spec:
      containers:
        - name: mysql
          image: mysql:8.0
          ports:
            - containerPort: 3306
          env:
            - name: MYSQL_ROOT_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: blog-secret
                  key: MYSQL_ROOT_PASSWORD
            - name: MYSQL_DATABASE
              valueFrom:
                configMapKeyRef:
                  name: blog-config
                  key: DB_NAME
            - name: MYSQL_USER
              valueFrom:
                configMapKeyRef:
                  name: blog-config
                  key: DB_USER
            - name: MYSQL_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: blog-secret
                  key: DB_PASSWORD
          resources:
            requests:
              cpu: 100m
              memory: 256Mi
            limits:
              cpu: 500m
              memory: 512Mi
---
apiVersion: v1
kind: Service
metadata:
  name: mysql-svc
spec:
  type: ClusterIP
  selector:
    app: mysql
  ports:
    - port: 3306
      targetPort: 3306
```

```bash
kubectl apply -f mysql-deploy.yaml
kubectl get pods -l app=mysql
```

MySQL이 완전히 뜰 때까지 기다립니다.

```bash
kubectl wait --for=condition=ready pod -l app=mysql --timeout=120s
```

## 3) Backend 배포

`backend-deploy.yaml` 파일을 만듭니다.

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: backend
spec:
  replicas: 2
  selector:
    matchLabels:
      app: backend
  template:
    metadata:
      labels:
        app: backend
    spec:
      containers:
        - name: backend
          image: skilleat/miniblog-api:v1.0.0
          ports:
            - containerPort: 8080
          envFrom:
            - configMapRef:
                name: blog-config
            - secretRef:
                name: blog-secret
          resources:
            requests:
              cpu: 100m
              memory: 128Mi
            limits:
              cpu: 300m
              memory: 256Mi
---
apiVersion: v1
kind: Service
metadata:
  name: backend-svc
spec:
  type: NodePort
  selector:
    app: backend
  ports:
    - port: 8080
      targetPort: 8080
      nodePort: 30080
```

```bash
kubectl apply -f backend-deploy.yaml
kubectl get pods -l app=backend
kubectl get svc backend-svc
```

## 6) 롤링 업데이트 — v2.0.0

v2.0.0은 게시글에 `author` 필드가 추가된 버전입니다.

새 터미널을 열어 Pod 변화를 실시간 감시합니다.

```bash
kubectl get pods -w
```

기존 터미널에서 이미지를 변경합니다.

```bash
kubectl set image deployment/backend backend=skilleat/miniblog-api:v2.0.0
kubectl rollout status deployment/backend
```

완료 후 헬스체크로 버전이 바뀐 것을 확인합니다.

```bash
curl http://localhost:30080/health
```

```json
{"status":"ok","version":"2.0.0"}
```

v2.0.0에서는 author 필드를 포함해 게시글을 작성할 수 있습니다.

```bash
curl -X POST http://localhost:30080/posts \
  -H "Content-Type: application/json" \
  -d '{"title":"두 번째 글","content":"v2에서 작성했습니다.","author":"홍길동"}'
```

```json
{"id":2,"title":"두 번째 글","content":"v2에서 작성했습니다.","author":"홍길동","version":"2.0.0"}
```

## 핵심 정리

- 각 계층은 Service 이름(DNS)으로 서로를 찾습니다. Pod IP를 직접 사용하지 않습니다.
- ConfigMap·Secret은 코드 변경 없이 환경에 따라 설정을 바꿀 수 있게 합니다.
- Backend가 기동될 때 DB 연결을 재시도(최대 10회)하므로 MySQL보다 먼저 떠도 자동으로 연결됩니다.
- v1.0.0 → v2.0.0 롤링 업데이트 중 기존 Pod가 살아있기 때문에 요청 중단 없이 교체됩니다.

## 트러블슈팅

| 증상 | 확인 사항 |
|---|---|
| MySQL Pod `CrashLoopBackOff` | Secret의 `MYSQL_ROOT_PASSWORD` 설정 확인 |
| Backend Pod 로그에 `DB connection failed` | MySQL Pod가 아직 기동 중 — 자동 재시도하므로 잠시 대기 |
| `curl localhost:30080` 응답 없음 | `kubectl get svc backend-svc` 에서 NodePort 30080 확인 |
| POST 후 GET에 데이터가 없음 | 다른 Backend Pod로 요청이 간 것이 아닌지 — 둘 다 같은 DB를 공유하므로 문제 없음 |
